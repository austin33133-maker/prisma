# 同类亚马逊卖家工具 — 开发技术方案

> 系列编号:8-策划-亚马逊的卖家精灵 · 文档 2/4
> 配套文档:[01-产品调研.md](./01-产品调研.md) · [03-数据模型.md](./03-数据模型.md) · [04-品牌定位与对标.md](./04-品牌定位与对标.md)

## 1. 产品定义(MVP 边界)

做一个「卖家精灵式」工具,MVP 聚焦数据价值最高、工程上可独立交付的四个模块:

1. **竞品查询**:输入 ASIN,展示销量/价格/BSR/评论的历史曲线(目标回溯 ≥ 12 个月)。
2. **反查 ASIN**:输入 ASIN,输出其自然/广告流量关键词及排名。
3. **关键词挖掘**:输入种子词,输出关联长尾词 + 搜索量 + 购买率。
4. **商品/关键词追踪**:用户订阅 ASIN 或关键词,每日更新并触发告警。

明确**不做**(二期再说):Listing 打分、利润计算器、广告洞察、店铺跟踪、浏览器插件。

## 2. 总体架构

```
┌─────────────┐   ┌──────────────────────────────────────────┐
│  采集层      │   │  数据层                                    │
│  Crawler     │──▶│  原始页面 → 解析 → ODS → 清洗/估算 → DWS    │
│  Fleet       │   │  (S3/对象存储)   (ClickHouse + PostgreSQL) │
└─────────────┘   └──────────────────────────────────────────┘
                                       │
                  ┌────────────────────┴───────────────┐
                  │  服务层 (Node.js/TypeScript)         │
                  │  API Gateway · 查询服务 · 订阅/告警   │
                  │  额度计费 · 任务调度                  │
                  └────────────────────┬───────────────┘
                                       │
                  ┌────────────────────┴───────────────┐
                  │  应用层:Web (Next.js) / 后续插件      │
                  └────────────────────────────────────┘
```

### 2.1 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 采集 | Playwright + 代理池,独立 worker 集群(K8s CronJob) | 反爬对抗需要真实浏览器指纹;与主服务隔离故障域 |
| 原始存储 | 对象存储(S3 兼容)存 HTML 快照 | 解析逻辑迭代后可回放历史页面重新提取 |
| 分析存储 | ClickHouse | ASIN×日期、关键词×日期的时间序列聚合查询是绝对主力负载 |
| 业务存储 | PostgreSQL + **Prisma ORM** | 用户、订阅、追踪任务、额度等强事务数据;模型见文档 3 |
| 服务端 | Node.js + TypeScript(NestJS 或 Fastify) | 与 Prisma 生态契合;团队栈统一 |
| 队列 | Redis Streams 或 BullMQ → 量大后迁 Kafka | 采集任务分发、告警事件 |
| 前端 | Next.js + ECharts | 曲线图密集型产品,ECharts 中文生态成熟 |

### 2.2 冷热数据分工(关键决策)

- **ClickHouse**:`product_daily_metrics`、`keyword_daily_metrics`、`keyword_rankings` 等高基数时间序列(亿级行),负责所有图表与筛选查询。
- **PostgreSQL(Prisma)**:用户域 + 元数据域(商品/关键词主档、追踪订阅、告警、套餐额度)。文档 3 的 Prisma schema 同时把指标表也建模出来,**小数据量阶段可全跑在 PostgreSQL 上,验证 PMF 后再把指标表迁到 ClickHouse**,Prisma 模型保留为类型契约。

## 3. 核心子系统设计

### 3.1 采集与解析

- 任务类型:`PRODUCT_DETAIL`(详情页)、`SEARCH_RESULT`(搜索结果页,用于关键词排名)、`BESTSELLER`(类目榜单,用于发现新 ASIN)。
- 调度策略:被用户追踪的 ASIN/关键词每日一采;全量库存 ASIN 按热度分层(周采/月采)。
- 失败重试 + 代理评分;解析失败的页面落对象存储待回放。
- **合规注意**:仅采集公开页面数据,遵守目标站点 robots 与当地法律,设置限速;商用前需法务评估。

### 3.2 销量预估引擎

口碑核心。MVP 采用经典混合模型:

1. BSR → 销量基线:按「站点 × 一级类目」维护 BSR-销量映射曲线(分段幂函数拟合,用少量自营测款数据 + 公开校准点标定)。
2. 评论增速修正:`reviewVelocity ≈ 销量 × 留评率(类目先验)`,与基线加权融合。
3. 库存探测法(加购上限探测)作为高价值 ASIN 的校准手段,低频使用。

模型版本号随指标行存储(见 schema 的 `estimateModelVersion`),便于回溯与 A/B。

### 3.3 反查 ASIN 与关键词图谱

- 每日对关键词池跑搜索结果页采集,记录「关键词 × ASIN × 排名 × 是否广告位」即 `KeywordRanking`。
- 反查 = 按 ASIN 倒排该表;关键词挖掘 = 词共现 + 亚马逊搜索下拉补全 + 词根聚类。
- 搜索量来源:ABA(品牌分析)公开排名数据反推 + 自有点击模型估算。

### 3.4 订阅、额度与告警

- 套餐只限制**额度**不限制功能(沿用卖家精灵被验证的定价设计):可追踪 ASIN 数、可追踪关键词数、每日反查次数、导出次数。
- 额度按「自然日 + 订阅周期」双维度计数(见 `UsageRecord`)。
- 告警规则:价格变动超阈值、BSR 跌出/进入 Top N、上新差评、断货;走队列异步推送(站内信 + 邮件,后续微信/飞书)。

## 4. 里程碑计划

| 阶段 | 周期 | 交付 |
|---|---|---|
| M1 基础设施 | 4 周 | 采集集群、解析管线、ODS 入库;PostgreSQL + Prisma 模型上线 |
| M2 竞品查询 | 4 周 | ASIN 历史曲线(美国站),销量预估 v1,Web 端查询页 |
| M3 关键词 | 6 周 | 关键词排名采集、反查 ASIN、关键词挖掘 |
| M4 商业化 | 4 周 | 注册/订阅/支付、额度计费、追踪与告警;公测 |
| M5 扩展 | 持续 | 日本/欧洲站点、浏览器插件、ClickHouse 迁移 |

## 5. 团队与成本(MVP 估算)

- 人力:后端×2、前端×1、数据/爬虫×2、产品兼设计×1,约 4.5 个月。
- 基础设施:代理池是最大变动成本(按采集量 $1k–5k/月起);ClickHouse 与 K8s 集群初期可单机/托管。

## 6. 主要风险

1. **反爬升级**导致数据断供 → 多采集通道冗余、页面快照回放能力。
2. **销量预估偏差**损伤口碑 → 公布置信区间,持续用真实订单校准。
3. **平台政策/法律风险** → 合规审查前置,数据脱敏,不存储买家个人信息。
4. **冷启动数据深度不足**(对手有 24 个月历史)→ 用「数据新鲜度 + 中文服务 + 价格」差异化切入,历史深度随时间自然累积。
